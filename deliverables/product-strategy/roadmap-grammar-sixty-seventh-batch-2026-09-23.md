## 2. ⚠️ 与 D 层守门的**两处刻意不同**（本批实现时踩出来的）

D 层守门把 `contrast.wrong`（错句）与 `guided[].tokens` 都算进词表，
因为它的命题是「**用户见没见过**这个词」。而本模块的命题是
「**这个词值不值得背**」：

| 来源 | D 层守门 | 本模块 | 原因 |
|---|---|---|---|
| `contrast.wrong` | 收 | **不收** | 错句里是刻意造的错误形式 |
| `spot` 题的 `answer`/`tokens` | 收 | **不收** | **`spot` 的 `answer` 就是那个错词**（用户要点出来）|

**实测：首版把两者都收进来，25 个错误形式混进词表**：
`putted`(L82) / `thinked`(L197) / `catched`(L199) / `keeped`(L200) /
`sleeped`(L201) / `drawed`(L202) / `weared`(L203) / `gived`(L204) / `haves`(L3) /
`goodest`(L31) / `fastly`(L59) / `breaked`(L23) 等。

**把 `goodest` 收进词书让用户背，是明确的缺陷。**

这与批五十三在 `HuntError` 上立的纪律**同源**：
**「答案」字段的语义要看题型，不能按名字猜。**

## 3. 已知限制（诚实登记）

词表里仍有**专有名词**（`xiaomei` / `xiaoming` / `lin` / `tao` / `tom`…）。
严格说，把 `xiaomei` 收进词书让用户背也不合适。

**未做的原因**：机器分不出人名与普通词（都得靠一张人名表），
而仓库里没有这份清单；硬编一张会随课文新增而失效。
⇒ 正确路径是**在课数据侧给人名打标**，而不是在服务里猜。
已写进服务文件头的「已知限制」。
