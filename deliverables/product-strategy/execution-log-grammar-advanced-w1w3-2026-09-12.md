## 5. 试玩发现（W4 定性观察，2026-09-13）

**发现 #1 · 无提示输出（R04）题干不唯一 + 缺台阶 → 已修**

| 项 | 内容 |
|---|---|
| 现象 | L13「最后一步 · 说出来」只给场景铺垫，用户填了同学问句 `What are you doing?`（同属该课例句）被判 0%；0% 时展示全红词块对照，被误读为「要用这些词拼」 |
| 根因 | ① 题干以「场景」指向核心句，不唯一（同一场景同时对应 dialogue 问句与 targetSentence）②「无提示」把靶子也一起拿掉了 ③ score=0 的反馈无信息量 |
| 修复 | 题干唯一化（「轮到小美说话……不是同学问她的那一句」）；新增三级提示阶梯（中文意图 → 开头骨架 → 答案），首答仍无提示以保住度量；score=0 不再展示 diff，改为引导要提示；遥测区分 `free_type` / `free_type_hint` |
| 结论 | 属 R04「无提示输出」的设计缺陷（非实现 bug）——已修复并写入内容管线技能，避免后续课程复现 |

**发现 #2 · arrange 题词块未打乱，点词成句退化成「顺序点选」→ 已修**

| 项 | 内容 |
|---|---|
| 现象 | L14 第 3/4 题词块库显示 `She can sing very well.`，与答案顺序完全一致——顺着点一遍即过关，题型失去意义 |
| 根因 | 内容数据里 `tokens` 多为顺手按答案顺序书写（新 8 课与第一季多数课均如此）；渲染层直接 `tokens.map()` 输出，无打乱 |
| 修复 | 渲染层新增确定性打乱 `shuffleTokenOrder(tokens, seed)`（mulberry32 种子化：同题顺序稳定、必然不等于原顺序）；词块库按打乱下标渲染，点击/拖拽仍记原始下标 → 判题零改动；新增守卫测试扫描 **全部 20 课 100+ 道 arrange 题**，任何一题顺序=答案即红 |
| 结论 | 一次修复覆盖全库并自动约束未来内容；数据层无需人工打乱（写入内容管线技能） |

**发现 #3 · 输出题反馈只说颜色 + 提示口径与判分不一致 → 已修**

| 项 | 内容 |
|---|---|
| 现象 | L15 写 `I want to go travel`（多一个 go）得 80%，只见红绿对照；而刚看过的提示是中文意图「我想去旅行。」——用户会认为「意思对就该算对」 |
| 判定 | **判分正确**（核心句为 `I want to travel.`，「go travel」非教材写法）；真问题是 ① 提示只给中文意图，与「逐字复刻核心句」的口径不一致 ② 反馈不点名差在哪 |
| 修复 | 新增 `describeOutputGap`：`多了一个词「go」——这一课的核心句是 4 个词。`／`少了一个词`／`顺序或个别词不太一样`；1 级提示补「按核心句写 + 共 N 个词」；题干补口径「按这一课的句型」；新增 5 条单测 |
| 结论 | 输出题的「提示—作答—反馈」三段必须共用同一口径，否则用户会觉得被冤枉 |

**发现 #4 · 前测结果页只说「有 N 处拿不准」，不说哪一题、为什么 → 已修**

| 项 | 内容 |
|---|---|
| 现象 | L14 前测结果页只显示「前测里有 1 处拿不准——这一课就是讲它们的」，用户无法知道是哪一题、自己的判断是什么、为什么不对 |
| 根因 | 解释数据本来就有（choose 的 `explain`、contrast 的 `whyZh`），但页面只计数不展示；`pretestWrongNotes` 是只写不读的死状态 |
| 修复 | 新增 `PretestWrongRecord[]` 结构化记录并在结果页逐题展示：`第 N 题 · 题面` → `你的选择/判断：X · 正确：Y` → `正确说法：…` → `为什么：…`；保留「拿不准」话术与复习队列提示；清理死状态 |
| 结论 | 「先试后学」的前测，其价值一半在暴露错误、一半在**说清错误**——只计数不说清，等于把疑问留到讲解里靠运气碰上 |

> 该发现恰好验证了 D1 决策门的价值：这类问题只有真实使用才暴露，而它出现在「最贵的第二批」之前。
