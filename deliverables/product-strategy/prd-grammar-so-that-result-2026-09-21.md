## 1. 修复一：错词本垃圾词（115 → 0）

### 1.1 缺陷

`src/services/huntService.ts` 的 `pickCorrectionWord` 从 `correction` 里挑一个词收进错词本。它原本只挡「`去掉` 开头」，于是两类脏数据进了库：

| 类型 | 处数 | 例 |
|---|---|---|
| 尾部标点未剥 | 102 | `first.` / `classmates.` / `the window.` / `day!` / `eat,` |
| 括注式整条未挡 | 13 | `（去掉 to）` → 挑出 `（去掉`；`（So 与 do I 对调）` → 挑出 `（So` |

**合计 115 处**（竞析独立复核成立，748 个植错点中：pick 非空 640 → 非纯英文 115）。分布极不均：后 100 案贡献 108/115（94%）。

### 1.2 修法（两行，顺序不可颠倒）

```ts
// 先判括注（整条跳过），再剥标点
if (trimmed.startsWith("（") && trimmed.endsWith("）")) return "";
// …
return meaningful.replace(/[.,!?;:]+$/, "");
```

**为什么顺序不能颠倒**（竞析的关键提醒）：只剥不判的话，`（So 与 do I 对调）` 会被剥成 `So`、`（rather 跟在 would 后）` 会被剥成 `rather`——**把「一眼可见的乱码」升级成「看起来对的错词」，比不修更坏**。

### 1.3 验证

| 项 | 修前 | 修后 |
|---|---|---|
| 非纯英文垃圾 | 115 | **0** |
| 可加词总数 | 640 | 627 |
| 「从有变无」的槽位 | — | 13（全是括注式，本就该跳过） |
| 原有正确词 | — | **零改动** |

原测试契约全部保持：`an`→`` / `a`→`` / `去掉 so`→`` / `moved`→`moved` / `is happy`→`happy`。

## 2. 修复二：重放题余量（23 → 1，余量 3 → 25）

### 2.1 缺陷

「重放题」守门的判据是：练习题的答案**逐字等于课内展示句**，且中文提示相似度 ≥ 0.8 —— 用户在看段已建立中英映射，练段不需组织。上限 26，实测已占 **23**，余量只剩 3 道。这是当前最硬的内容约束，会让后续每批新课都触线。

### 2.2 根因（本批新发现）

拆开 23 道看：**15 道撞的是 `sceneSwings`**，其余撞 `examples`。而 `sceneSwings` 是「同一个句子在别的场景里怎么说」的展示结构——它和练习题的重复是**结构性的**，不是内容偷懒。

**关键判断**：测试注释明确写着判据优先级不可颠倒——
1. 提示与答案语义一致 ← 最高优先级，破坏它就是坏题
2. 答案不与看段重复 ← 可优化项

所以修法**不能改练习题的提示**，只能改**被复制的展示句**。

### 2.3 修法

把那 23 处「被练习答案逐字复制的展示句」换成同结构新句，练习题与提示保持不动：

| 课 | 展示句（旧 → 新） |
|---|---|
| L3 | `I have a new bike.` → `I have a small cat.` |
| L5 | `I like cats.` → `I like pandas.` |
| L12 | `We will go to the park tomorrow.` → `…to the zoo…` |
| L17 | `This apple…` → `This orange is bigger than that one.` |
| L69 | `…closing the door?` → `…closing the window?` |
| L166 | `There is too much homework.` → `…too much noise.` |
| L173 | `She studies hard in order to pass the test.` → `She gets up early in order to catch the bus.` |
| … | （共 23 处，详见数据 diff） |

**过程中踩到的三个坑（已修）**：
1. 换掉的展示句是练习答案的**词源**——L3 的 `bike`、L10 的 `football`、L12 的 `run` 因此变成「未教词」，触发 D 层闸门。改为换用课内已有词。
2. 换后的展示句**又和练习题撞**（如 L12 的 `I will come tomorrow.` 两头都出现）——再换展示槽。
3. L115 整组练习变成「全是课内句」，触发 C 层闸门——补一道新句 `She has got a new car.`。

### 2.4 验证

| 项 | 修前 | 修后 |
|---|---|---|
| 重放题 | 23 / 上限 26 | **1** / 26 |
| **余量** | **3** | **25** |

## 3. 内容：L193 `so ... that`

### 3.1 裁定：做 1 课，拒绝 `such a`

**两位研究结论相反**，这是本批最重要的裁定：

| 来源 | 结论 | 核心理由 |
|---|---|---|
| 瑞思 | **做 1 课**（`so...that`），拒绝 `such a` | 可做性成立（3 条带标记错句）；`such a` 与 L89 撞车且牛津标 A2 更晚 |
| 竞析 | **不做（0 课）** | 跨源粒度不匹配（BC 一课吃三形态）；与 L186 冲突且成本是「改旧课」；不治稀缺瓶颈 |

**裁定：做 1 课，拒绝 `such a`。** 我采纳瑞思的结论，但理由取两者的交集而非单选：

1. **竞析的核心顾虑「与 L186 冲突」经核实反而支持做。** L186（`so that` = 是为了）的 `summary.points` 里**已经提前排过一行**：「so（所以）／so that（是为了）—— 一个说结果，一个说目的」。也就是说 L186 已为「多张脸」预留了位置，本课是**补第三张脸**，不是打架。
2. **竞析的「粒度不匹配」成立，但恰好是本课的边界。** 本课**只做 `so ... that`**，不碰 `such`、不碰 `so much/many`——粒度与本项目历史一致（L191/L192 都是 1-2 个点）。
3. **拒绝 `such a`**：与 L89 的 `What a nice day!` 是同一个「a 站哪儿」的坑，属项目判定过的「换词」；牛津标 A2 比 `so…that` 的 A1 晚一级。
4. **瑞思纠正了我两个背景数字**（属实，已采纳）：`too ... to` 不是 0 而是 GL 51（L66 立岗，且已有一条带标记错句）；`so that` 不是 5 处而是 61 处（原口径只查了三个字段，全字段是 226/61）。

### 3.2 设计

- **targetSentence**：`The wind was so strong that the window broke.`（9 词，最长分句 9；难度跳变 0，与 L192 同级）
- **scene**：`lighthouse`（台风夜的灯塔，与前课间隔充分）
- **核心增量**：`so` 的**第三张脸**——

| 脸 | 出处 | 形态 | 意思 |
|---|---|---|---|
| ① | L20 | `…, so I ate noodles.` | 所以（站自己一句开头） |
| ② | L186 | `I came early so that you can rest.` | 是为了（so that 连着写） |
| ③ | **L193（新）** | `The wind was so strong that…` | 太…了所以（中间隔着「有多…」那一小截） |

给用户的自测判据：**看 so 后面跟什么**——跟「一整件事」是第一张；跟 `that` 是第二张；跟「有多…」那个词是第三张。

- **3 条带标记错句**（都有剑桥逐字支撑）：
  1. `very` ❌（剑桥原文：`We do not use very in this structure`）
  2. `that` 后缺「谁」❌（`that broke the window`）
  3. `such` ❌（剑桥原文：`Not: You're such kind.`）
- **3 条双正解**：分别对照 L20 的 `so`（所以）、L186 的 `so that`（是为了）、L66 的 `too…to`（做不到）
- **案件 #202「灯塔上的裂缝」**：4 处错 = `very→so`（word_order）· `that` 后缺「谁」（fragment）· `She have`→`has`（L3 回流）· `buyed`→`bought`（L11 回流）

## 5. 方法学教训

1. **我犯了一次批量替换失误**：用 `.replace(/toBe\(192\)/g, "toBe(193)")` 无差别全局替换 `src/edge` 的计数，可能误伤语义无关的数字。事后逐项审计确认**未造成实际损害**（`654`/`369` 等保持原值），但这个手法本身不安全——**应始终带上下文限定**（如 `/grammarLessons\.length\)\.toBe\(192\)/`）。
2. **测试文件数从 91 涨到 140（并发进程新增 49 个诊断套件）**，其中 28 项失败全部是它们登记的**全库既有缺陷或基线漂移**，与本批无关。判别方法：看断言标题是否带「已确认缺陷」「当前行为」标注，以及失败样本是否从 `lesson-01-am` 起（即全库共性）。
3. **并发进程自己解决了基线漂移**：`gq1` 的基线从绝对数改成**比例**（`656/3609 = 18.2%`），我的数据增长自动被吸收。
4. **两位研究的分歧要取交集而非单选**：竞析说「不做」，其核心顾虑经核实反而支持做；但它的「粒度」与「拒绝 `such a`」两条约束被完整保留。
