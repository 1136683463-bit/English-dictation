# 路线图 · 第七十批（修首页到期口径不一致）

- 日期：2026-09-24
- 交付：**修 `EntryPage` 的「今日到期」口径** + 新增守门 `rv19`（已提交 `d1dcac6`）
- 方法：**用用户真实数据状态走一遍首次动线**，找具体摩擦点

---

## 1. 怎么找到的

按上一批的建议「查第一次复习为什么没发生」，我用**用户真实数据的状态**
（115 张卡全是 `new`、`nextReviewAt` 已过、无 reviews）复刻，
逐页走了一遍首次动线：`/`（EntryPage）→ `/today` → `/review`。

**机制是通的**：`getNewCardsForToday` 返回 10 张/天（与 `settings.dailyNewWords: 10` 一致），
115 张约 12 天走完；所有链接指向正确。**但发现一处数字自相矛盾**：

| 页面 | 显示 |
|---|---|
| 首页 `/` | 今日到期 **115** |
| 今日 `/today` | 到期复习 **0** |

---

## 2. 根因：两份口径

```ts
// EntryPage.tsx（就地数排期）
data.schedules.filter((s) => new Date(s.nextReviewAt) <= new Date()).length

// 全站其它地方（权威口径）
reviewService.getDueCards(data).length
```

逐个卡状态实测，两者在**三种状态**上不一致：

| status | 排期已过 | EntryPage | getDueCards |
|---|---|---|---|
| `new` | 是 | **1** | 0 |
| `mastered` | 是 | **1** | 0 |
| `suspended` | 是 | **1** | 0 |
| `learning` / `review` | 是 | 1 | 1（一致）|

**`getDueCards` 排除 `new` 是 R1 的有意设计**（`reviewService.ts:107-109`：
新卡走每日新卡队列、不进口「到期」桶）——**不是缺陷**。
**缺陷在首页没走同一套口径。**

⇒ 对刚导入词卡的用户，第一印象是「数字明显不对」。

---

## 3. 修法

首页改读 `getDueCards(data).length`，与今日页/统计页统一。
**没有引入新逻辑**——只是让首页用已有的权威口径。

---

## 4. 守门 rv19（5 项）

**`EntryPage` 此前一个测试都没有**——全库搜 `EntryPage` 只出现在 `App.tsx` 的路由里。
这正是它能长期不一致的原因。本闸同时补上「这个页面有测试」：

| # | 断言 |
|---|---|
| ① | `new` × 115 张排期已过 → 首页显示 **0** |
| ② | `mastered` → 0 |
| ③ | `suspended` → 0 |
| ④ | `review` × 7 → 显示 **7**（这是真的到期）|
| ⑤ | **闸自检**：同样 10 张排期已过的卡，`new` 显示 0、`review` 显示 10，**两者必须不同** |

**自检**：回退旧口径 → 4 项变红，且**精确复现** `expected 115 to be 0`；还原 → 5 项全绿。

## 5. ⚠️ 被仓库自己的时间炸弹扫描器抓了一次

本闸第一版写死了「距今天 14 天」的 ISO 日期，被
`lg4-time-bomb-tests.test.ts` 判为危险：

> 真正危险的是「写死**近期**日期 + 时间衰减」——这种组合应为 0

**它说得对**：我今天写 09-10 是「14 天前」，几个月后它仍算过期、
但已不是「近期」，而判据的本意是「排期已过」，与「近期」无关。

改用仓库既有的 `PAST_ISO`（2024-01-01）——既表达「已过期」又不触发时间衰减。
**这条经验写进了测试注释**（含「为什么不能写死日期」的理由）。

⇒ 这是本会话**第二次被仓库既有守门抓住我自己的错误**——
第一次是批五十七：我建的 RV11（editOp 自洽性）抓到我自己的错标
（`left` → `had left` 标成 `replace`，字面推断应是 `insert`）。
其余十几次口径缺陷都是自查发现的。

**守门在这里起了它该起的作用**：我写测试时不会想到「写死日期会随时间失效」，
而仓库里已经有一道专门查这件事的闸。

## 7. 本批对「第一次复习为什么没发生」的贡献

**修掉了一个会直接影响首次印象的缺陷**，但**它不解释「为什么没复习」**——
机制是通的（10 张/天、链接都正确）。

从证据看，「没开始复习」最可能仍是**「那批数据来自构建/验收阶段的试用」**
（数据 09-16 停了、开发继续 8 天）。这一点**仍需用户确认**。

⇒ 本批的价值是：**在下游追查过程中修掉了一个真实存在的、用户可见的缺陷**，
而不是又加了一个功能。
