# 第一部分 · 裁定（析客）

**首页需要重新规划，但不是「三线并列」的重规划，而是「范式收窄 + 三线常驻可见」的轻手术（方案 B）。**

| 方案 | 内容 | 否决 / 采纳理由 |
|---|---|---|
| **A 不重规划**（只补冒险） | 把冒险塞进现有结构（Hero action 槽或第 6 行任务） | **否决**。只修「看不见」，不修「自相矛盾」：真实数据下 Hero 文案「建议可以推进新词」与按钮「继续第 1 课」是**代码 + 数据的必然结果**，A 不触碰根因；且把冒险塞进 action 槽会直接撞 `rv15:88`，等于制造「推荐与文案不同源」的第二例；两个首页的问题原封不动 |
| **B 轻手术（推荐）** | ①主 CTA 与 Hero 文案**同源**（`buildHomeDirective` 单一决策）②三线常驻**细行**（不是等权大卡）③次级枢纽 `TrainingPage` 补齐三线入口 ④两个首页收敛为一 ⑤先补冒险遥测读侧出口 | **采纳**。用**零新增数据字段、零 schema 变更、零新增路由**拿到发现性的 80%，同时修掉决策成本与自相矛盾两个真问题。唯一需改测试处是 `rv15` 的闸自检判据（**判据升级**，非绕过） |
| **C 三线并列枢纽** | 首页改三条线各一个并列区块（数析推算「两屏内放得下」） | **否决（本期）**。数析的推算正确，但它答的是「**放得下**」这个空间问题；瑞思与竞析答的是「**该不该放**」。C 的成本：每次会话都要付排序决策（三线进度语言互不相同 `0/30`、`0/205`、第 8 章，无法比较）、把语法线内部已实测的「3 套守卫态 / 2 个同名目的地」放大 3 倍、移动端必须**同时**改 Banner 与 strip 才腾得出空间，代价是「最近错误」与「继续词书」被推到第 3 屏。而它买到的发现性，细行就能买到 |

### 分歧裁决（正面处理三位研究员的真实分歧）

数析倾向「可并列」并给了预算推算；瑞思与竞析明确反对等权并列。裁决方式——**说明各自成立的条件，而不是和稀泥**：

- 数析的「可并列」成立条件：**问题只有发现性**（空间够、放得下、用户能自己挑）。
- 瑞思/竞析的「不可并列」成立条件：**决策成本已高于发现性收益**。

本项目的事实是**两个问题同时存在**：发现性 = 0（冒险首页引用 0，硬缺陷）**且**决策成本已经过高（8 天 0 写入；首页 5 处裸 0 仪表盘）。

⇒ 所以正确解法不是二选一，而是**把两个问题解到不同的容器里**：
- **发现性**交给「常驻细行 + 次级枢纽」——一次性成本，不付每次会话的排序决策；
- **决策成本**交给「单一推荐 + 同源 + 一行解释」。

据此：**采纳数析的空间结论**（移动端预算必须腾出来），**不采纳它的并列结论**；**不采纳瑞思的「冒险放任务队列首位」措辞**（那会让三线顺序被人为固定，与用户真实状态脱钩），改为按最近活动排序。

### 需修正上游两处

1. **数析建议 3 的公式 `min-height: min(224px, 34vh)` 是空操作**：375×667 时 34vh = 226.8px ⇒ min = 224px；1440×900 时 34vh = 306px ⇒ min = 224px。要真正压低 Banner，必须在 `@720` 断点内用更高特异性选择器**显式给值**。
2. **数析「冒险 6 段：城市寻信 3 章」与其自身实测不符**：backup 里两段「城市寻信」各只有 1 个节点，全库共 **17 个节点**（后续一律按 17 计）。

# 第二部分 · 问题陈述（析客）

**谁的问题**：唯一用户（= 产品负责人 = 开发者）。

**三个可证伪的具体问题**：

1. **内容投入与曝光倒挂，且与真实消费完全反向**。数析实测：语法 499+ 单元 → 首页 2 个可点目标；冒险 136+ 单元 → **0**；词汇 115 卡 → 14 个可点目标中的 12 个。而**唯一有真实消费的线恰恰是曝光为 0 的那条**（冒险 6 段 17 个故事节点，3 段被真读，11 次选择，「海岸列车」一次会话连读 8 章）。瑞思把「冒险在首页内容体引用数为 0」判定为**线索断层**，影响度「高」，频率「每次打开首页 = 100%」。
2. **首屏自相矛盾（代码必然）**。`TodayPage.tsx:104-111` 的 `primaryTask` 只看词汇三数（`dueTotal / weakWords / availableNewWords`），`grammarTarget`（`TodayPage.tsx:92`）只看语法，两者在同一块 Hero 里并列显示：真实数据下必然渲染成「建议**可以推进新词**，先练 6 分钟」+ 主按钮「继续第 1 课」。

**规模**：不涉及用户增长、收入或留存；只涉及**每次打开 app 的第一屏是否回答「现在做什么」**。连续 8 天 0 学习写入是这条路径的观测结果（瑞思标注为「中等强度」推断，另有「内容开发占满了他」的同容纳解释——本规格只做**降低首屏决策成本**，不主张「他放弃了产品」）。

## 5.2 主 CTA 推荐规则（可判定，纯函数，单一返回值）

规则全部在 `buildHomeDirective(data, now)` 内实现并只算一次，**Hero 的 desc、CTA 文案与落点、note 说明行、三线行排序四处共用同一个返回值** ⇒ 结构上不可能不同源。

**R1 · 续上优先**：三线各产出一个「中断点」候选，取最近活动者（同分时按 冒险 > 语法 > 词汇 固定序）：
- 冒险：`sortAdventuresForList(data.adventures)[0]`，条件 `nodes.length > 1` 且最后节点 `selectedChoiceId` 为空 且 `updatedAt` 在 7 天内 → CTA「继续〈标题〉第 N 章」→ `/adventure/:id`
- 语法：`listDueGrammarReviewCards(data).length > 0` → CTA「复习 N 个语法句」→ `/grammar/review`
- 词汇：`stats.dueTotal > 0` → CTA「先清 N 个到期」→ `/review`

**R2 · 无中断点时的回退链（已开始的线优先）**：
1. `summarizeLessonProgress(data).done > 0` → 下一课 → `/grammar/lesson/:id`
2. `stats.availableNewWords > 0` → 「推进新词」→ `/training`
3. `listDueGrammarReviewCards(data).length > 0`（新卡排除后的到期）→ `/grammar/review`

**R3 · 全空兜底**：无卡、无课、无冒险 → 「先去添加内容」→ `/add`。

**这条规则如何修掉瑞思的第 1 号发现**：真实数据下 R1 不命中 —— 0 到期、0 课、冒险侧**因 7 天窗口不成立**（最深的「海岸列车」8 章停在 2026-09-10，距复核日 14 天；`nodes.length > 1` 的另外两段也在同一天）；R2-1 不命中（`done = 0`）；R2-2 命中（`availableNewWords = 115`）⇒ **desc 与 CTA 同时变成「推进新词」**。矛盾消失不是靠改文案，是靠**让文案与按钮读同一个变量**。

## 5.3 「为什么是它」说明行

- **位置**：Hero 内、`description` 之下、action 之上（`BannerHero` 新增可选 `note?: ReactNode`，仅 `TodayPage` 传入；`TrainingPage` 调用点不受影响）。

## 6.1 三种首页范式

**范式 A · 单一线性路径 + 次级枢纽页（Duolingo）**〔未核实（官网博客直连实取）〕
首屏就是一条 path："The home screen is now designed as a path that you'll follow step by step"，一个圆点 = 一课。**多线不是首屏并列，而是塞进独立 tab**：官方 Practice Hub 指南列出 Mistakes / Words / Speak / Listen，以及 Stories / Radio / **Adventures** —— 即故事、广播、冒险三条内容线**恰恰不在首页路径上**，在 barbell 图标后的枢纽页里。改版动因官方写明：旧首页 skills 分离、每技能 5 个 crown level，练习与故事要离开主路径去导航，用户**"不确定自己是不是用对了 Duolingo"**。代价：2022-08 由「树状可选」改「线性推进」，社媒批评，CEO 表示不回头 —— **用自由度换明确性**。

**范式 B · 到期队列驱动的复习台（Anki / WaniKani）**〔未核实（官网文档直连实取）〕
Anki：首屏 = 牌组列表，每行显示当天 New / Learn / Due 三计数；点进牌组 = deck overview → **唯一按钮 Study Now**。多线＝多个牌组并列成货架，但每行只暴露「今日欠多少」。WaniKani：dashboard 由小组件拼成（Reviews / Lessons / Level Progress / Review Forecast），可自定义可拖拽。二者共同点：**回归不需要仪式感，只需要一个欠账数字**。

**范式 C · 内容货架 / 库驱动**〔已核实自研材料：`competitive-analysis-wordbook-2026-09-13.md`〕
该报告「信息架构」维度实测 8 家：List 背单词「主界面即 List」、Anki「主界面即牌组」、墨墨「选词前置流程」、百词斩「底部 Tab 直达」；「发现效率（3 秒知道今天做什么）」一栏里，功能多的产品被判 ◐「功能多干扰」，墨墨 / List 因「打开即背」被判最强。

**关于「三条线平铺首屏」**：本轮检索**未找到成熟先例**；最接近的是「一条主路径 + 一个次级枢纽」，而 Duolingo 的三条副线全在 hub 里。此为「未检索到」，不等于「不存在」——标**未核实**。

## 6.3 定位分析：「并列」还是「单一」？

**核心约束不是「多线如何并列」，是「一个人如何在 8 天中断后重新开始」。** 三条已验证机制与可移植性：

1. **队列即回归（Anki / WaniKani）**〔未核实〕：回来第一屏第一句话是「你欠 N 张」，不需意志力决策、不含道德评判。**但本项目硬伤**：115 张卡全部 `new`、0 复习，**队列此刻是空的** —— Anki 式首页在零到期时不给任何引导，这正是「新用户第一天不会用 Anki」的原因。
2. **宽限而非刚性（Duolingo Streak Freeze）**〔未核实〕：立意是「给人 slack 比给刚性规则更有动机」。**本项目不能照搬 streak** —— `prd-grammar-boost-2026-09-18.md` 逐字「不做 streak / 排行榜 / 徽章压力，不用红色或『未完成』字样施压」；`team-review-adventure-2026-09-13.md` 十条红线含 streak / 推送。**能拿的是原理**：中断 8 天后，首屏不许出现「你已中断 8 天」，也不许生成「补做 8 天」的惩罚性队列。
3. **单一路径的价值是「消除我是否用对了的疑虑」（Duolingo）**〔未核实〕：官方把改版动因写成用户「不确定自己有没有用对」。我方今天等价的疑虑是「**新增的语法线、冒险线，我现在到底该不该碰**」—— **首页一个字都没回答**。

**结论**：**「单一推荐动作 + 次级枢纽」比我方现状更接近已验证实践**；但单一推荐必须能**指向三线中的任意一条**，而不是锁死在语法线。

**本项目自己已踩过一次「多入口平铺首屏」的坑**〔已核实自研材料 `ux-research-grammar-2026-09-13.md`〕：`/grammar` 路径页首访「第一屏被 5 个平级入口 + 弱点卡 + 导出卡淹没」，主线「第 1 课」视觉最弱，用户状态判为「低（茫然）」。这是「并列即茫然」的**自有实证**，比任何竞品推断都硬。

## 6.4 优劣势对比

**范式 A 单一路径 + 次级枢纽**
- 可借鉴：① 首屏只回答一个问题「现在做什么」；② 有「跳回当前位置」能力；③ 副线不散进侧栏第 N 项，而是**给一个带图标、有名字的 hub**。
- 不适配：① Duolingo 能「单一」是因为只有一门语言的顺序课；我方三线是三种**不同构**行为（记忆 / 语法 / 叙事），谁当「当前节点」需要编排逻辑，而数据基础不存在；② 它节点有「未完成则不可跳」的强约束，我方三线随时可进，形成不了天然下一节点。

**范式 B 到期队列 / 仪表盘**
- 可借鉴：① 每线只暴露**一个数字**（欠多少）；② 回归靠队列、不靠打卡；③ 选择权下沉到一个**可选**的 picker，默认永不是多选题。
- 不适配：① 队列目前为空（全 `new`、0 复习）；② 只有词汇线有「到期」语义，语法是「下一课」、冒险是「继续第 N 段」，硬凑三个数字会得到一个**自己没有能力消费的仪表盘**。

**范式 C 内容货架**
- 可借鉴：① 首页一级入口直通内容（我方门页其实是此范式，只是只挂了词汇）；② 「打开即背」的极简首页在竞品里被反复评为发现效率最高。
- 不适配：① 无内容运营时货架越大越像清仓；② 该范式的成功依赖「内置 400+ 词书」，我方自建为主。

# 第七部分 · 用户研究洞察（瑞思）

**方法说明**：产品负责人 = 唯一用户 = 开发者本人，所以本轮不做用户画像与访谈（会虚构），只做三件合法的事：① 对真实行为数据做行为分析；② 复用上一轮 9 条真实反馈的主题编码；③ 用信息架构与无障碍判据审视当前设计。

## 7.1 关键发现

**1. 首屏第一眼：他最想做的三件事，当前首屏只答得上一件**
按行为数据推断，他打开 app 最可能想做：① **把上次没读完的故事读完**（6 段冒险里 3 段被真读过，共 14 章、11 次选择，「海岸列车」一次会话连读 8 章，09-10 12:24→12:44），这是三条线里**唯一**产生过重复消费的行为；② **看两条新线走到哪了**；③ **清到期复习**（他作为作者希望自己做的事，14 天里发生 0 次）。
当前 `/today` 把 ③ 做得最足，对 ① 是 0（引用数 0），对 ② 只给一个「第 1 课」按钮、不告诉他「你上次到哪」。
**更硬的问题：首屏内部自相矛盾** —— 真实数据下 `dueTotal=0 / weakWords=0 / availableNewWords=115`，Hero 文案**必然**渲染成「建议**可以推进新词**，先练 6 分钟」，而同一块 Hero 的主按钮是「继续第 1 课」→ `/grammar/lesson/...`。**一句话推荐词汇、按钮开语法，是代码 + 数据的必然结果，不是偶发文案问题**。摘要条那四个数字在他的数据下全为 0（无信息量）。另外真正的启动首屏是路由 `/` 的 `EntryPage` —— 4 个按钮全是词汇线，而侧边栏又把 `/today` 也叫「首页」：**「首页」指哪一个是模糊的**。

**2. 洞察 · 线索断层：唯一有真实消费的内容线，首页内容体引用数为 0**
- 证据 A（行为）：冒险 14 章、11 次选择，是唯一有重复消费的线；词汇 0 次复习；语法 0 课且桌面端从未打开。
- 证据 B（代码）：`TodayPage.tsx`、`EntryPage.tsx`、`StatsPage.tsx` 中 `adventure|冒险` 匹配数为 **0**（exit=1）；`EntryPage.tsx` 的 `grammar|语法` 也为 0。
- 证据 C（契约）：`rv15-today-grammar-entry.test.tsx` 的闸自检把 `adventure` 列入禁止落点正则 —— 「今日页不给冒险入口」是被测试固化的契约，不是疏漏。
- 证据 D（露出面）：冒险只存在于侧栏 / 移动底栏第 3 项、`TrainingPage` 七行列表之一、错词本下拉；`StatsPage.tsx:631` 的语法区块还带 `lessonProgress.done > 0` 前提（他的数据下统计页连语法也不显示）。
- 证据 E（跨线回流断裂）：「冒险积累」词书 `order=6`、**0 张卡**，而 17 章叙事里标出的生词共 116 个，**收词率 0/116**；且 order 6 也进不了首页那 4 张词书卡（`slice(0,4)`）。

**影响度：高** —— 它同时否掉「首页反映他真实在做的事」与「冒险有任何回流入口」。**频率：每次打开首页 = 100%**。

**3. 「Next Best Action」范式的代价与边界条件**
单一推荐动作成立的三个前提：系统与用户共享同一目标函数、推荐可解释、推荐错了代价低且易覆盖。**三条线不满足第一条** —— 间隔重复 / 课程阶梯 / 叙事消费**没有共同货币**，「先做哪个」需要一套跨线权重，而产品没有任何数据支撑这套权重（0 复习、0 课、只有 14 章叙事）。于是单一 CTA 退化为**代码里写死的那一条**。代价：① **永久盲区**（未被推荐＝整条线不可见，且没人会察觉，正是语法线此前的处境）；② **不可解释**（首屏最显眼的字是英文 eyebrow "Next Best Action"，却无一处说明「为什么是它」，而这位用户对解释质量的要求有 4 次反馈的强度）；③ **文案与动作可分离**（已实际发生）；④ **失败路径是关窗**（只提供一个动作，不想做那个动作时就没有第二条路，8 天 0 写入是这条路径的观测结果）。
**必须换成并列枢纽的边界条件**：三线无共同货币；推荐无法解释而用户要求解释；会话目标在「5 分钟」与「30 分钟」之间切换；被推荐项长期恒定（「第 1 课」会永远显示同一个目标）；任一条线存在未完成的中断点。

**4. 三条线共存的用户成本：并列 3 线 vs 单一推荐 + 次级入口**
- 决策成本：并列把「今天做哪条」从零决策变成每次会话都要付的排序决策，且三线进度语言互不相同（`0/30`、`0/205`、第 8 章），用户要先在心里换算才能比较。**连续 8 天没有学习写入说明瓶颈是「打开后没有一件确定能做的小事」，而不是「选项太少」**。
- 首屏预算：移动端可用高度 454px，Hero 占 ≥224px，摘要条约 200–230px 已把它用满，三个等权大按钮只会把「开始」推到首屏之外。
- 固定开销：三条线各有守卫态与口径，审计已实测语法线内部就有 3 套守卫标题、2 个名字指同一目的地 —— **在三条线统一之前就把它们并列，等于把不一致放大 3 倍**。

**判断：单一推荐 + 常驻的次级线行（每行 = 线名 + 上次位置 + 上次时间）更适合他。** 并列要解决的是发现性，而发现性的最小充分形式是「常驻可见」，不是「等权抢占主按钮」。保留单一推荐的前提是：与文案同源、给一行「为什么」、并且可回落。

**5. 移动端约束的硬限制（定量）**
可用高度 = 667 − 213 = **454px**；Hero 一项吃掉可用首屏的 **49%**（224/454），只剩 230px，装不下摘要条（200–230px）外加任何第三区块。**「把三条线都放上移动端首屏」在数学上不可行**。可行解只有一条：**不扩底栏项数，三线切换放进首页内容区（细行，不是大卡）。**

**6. 失败模式清单**

| 1 | 三条等权大按钮占据 Hero / 摘要条位置：10 秒内要做排序决策；移动端 3 个按钮把摘要条推到 454px 以下，首屏等于没有「开始」 | 主 CTA 保持唯一；三线用细行（含进度与上次位置）常驻，不做等权大按钮 |

# 第十部分 · 需求池（P0/P1/P2 与 RICE）

**Reach 口径（路径自定义）**：单人产品「多少用户」恒为 1，无区分度。沿用上一轮「触达回合数」骨架，把「不可逆系数」升级为四值 **K = 呈现强度 / 后果系数**：

| K | 含义 | 适用 |
|---|---|---|
| **2** | 不靠眼睛触达，但决定其余读数可否成立、或漏了不可逆丢数据 | 仪表类（遥测、容量、闸） |
| **1** | 经过即看见，不需额外动作 | 首屏 Hero / Banner / strip |
| **0.5** | 经过但需滚动或一次点击，或同视口内与其他目标竞争 | 内容区第 3 块、次级枢纽入口 |
| **0.25** | 只在特定状态下的特定时刻出现（条件渲染） | 章节末提示、空态组件 |

**为什么必须加 K**：数析实测移动端 375×667 首屏**只有 3 个可点目标** ⇒ 在这个产品里「存在 ≠ 看见 ≠ 起作用」。旧口径把「渲染出来」等同于「被触达」，会把条件渲染的入口高估 4 倍 —— 而瑞思的 3 次反馈「有时候有按钮有时候没有」正是这一族。K = 2 的定义与上一轮「不可逆系数 2」**逐字相同**，所以仪表类项两轮读数可直接比较。

**T 是约定，不是实测。** 20 是假设（20 天窗内每天至少一次首页会话），**无日志支撑**：`settings-telemetry-events-v1` 只有 9 条且不含页面浏览事件。两条纪律：① 本轮 RICE 数值**只用于排名**，不得读成收益预测；② 让 T 从约定变实测的唯一零成本办法是**人工会话日记**（每天记「打开首页几次 / 有没有点过冒险行」，5 秒），因为 v1 Non-goal 明令不新增遥测键。**稳健性**：若窗口内实际 T 只有 10，全部首页项的 R 同比例下调，**相对排序不变**。

**Impact（0–3）**：3 = 直接改变真实消费行为的量；2 = 显著改善已发生消费的质量 / 可信度，或使本轮决策变得可判定；1 = 体验打磨；0 = 无可观测行为改变。
**Confidence（0–1）**：**0.95** = 代码行号 + 实测数据双重支撑；**0.8** = 有代码路径，效果量靠推断；**0.6** = 方案成立但效果**改前不可证伪**；**≤0.5** = 依赖价值判断或未来数据。
