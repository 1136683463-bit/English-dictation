## 0. 一句话

竞析查出：**13 处「移动型」修正被 `correctedSentenceOf` 误判为删词**，生成 `My friend has a cat She was excited…` 这样的**粘句病句**，而它们**会进错词本的例句**——用户会看到并记住病句。这比上批修的 UI 文案严重。

---

## 1. 修复一：移动型修正生成粘句病句（最严重）

### 1.1 缺陷

数据里 13 处修正写作 `去掉（white 放到 cat 前面）`，而 `correctedSentenceOf` 的分支判断是：

```ts
if (/^（?去掉|去掉/.test(correction)) { tokens.splice(index, 1); continue; }   // ← 误判为删词
```

于是 `white` 被**删掉**，句子变成：

| 题面 | 误生成的修正 |
|---|---|
| `My friend has a cat white. She was excite…` | `My friend has a cat **She was excited**…`（**两句粘成一句**）|
| `I run a week twice. Two shoe are here.` | `I run a week **Two shoes are here.**` |
| `Please give the glue me. Two ruler are here.` | `Please give the glue **Two rulers are here.**` |
| `I waited an hour for. I wait for an hour.` | `I waited an hour **I waited for an hour.**`（重复）|

**这些病句会经 `correctedSentenceOf` 进错词本的例句**——用户会看到并记住。

### 1.2 修法（竞析建议，我实测确认）

把数据文案从 `去掉（X 放到 Y 前面）` 改成 **`把 X 移到 Y 前面`** —— 天然不匹配 `/^去掉/`，于是走「纯中文说明 → 保持原样」分支（该分支本就是为「句子层无可靠机械改法」而设）。

**选改数据而非改代码**：改正则要处理 `去掉（去掉）`、`（去掉 to）` 等边界，容易漏删；改文案只动 13 处，且新措辞**更准确**（它本就是「移动」不是「删除」）。

**修后**：`My friend has a cat white. She was excited…` —— `white` 保留在原位，粘句消失。

### 1.3 连带的连锁缺陷（我改完文案后自己发现的）

改文案后，`pickCorrectionWord("把 white 移到 cat 前面")` 返回 **`「把」`** —— 一个中文虚词会进错词本。这是**我的改动引入的**。

**修法**：`pickCorrectionWord` 加「含中文整条跳过」（它本就是说明性文案，不是可背的词）。修后全库入库词**非纯英文 0 处**。

## 2. 修复二：UI 文案「缺了一块」不准确（13/52 张）

### 2.1 缺陷

`GrammarLessonPage.tsx` 对 `wrongMark` 为空的卡一律显示「缺了一块」。我全库实测 52 张的真实形态：

| 形态 | 张数 | 「缺了一块」准确？ |
|---|---|---|
| 真缺词（`I am student.` → `I am a student.`）| **39** | ✓ |
| 词序不对（`Is it three o'clock?` → `It is three o'clock.`）| **9** | ✗ |
| 多了一个 not（`I am not happy today.` → `I am happy today.`）| **2** | ✗ |
| 等长替换（`It cold today.` → `It's cold today.`）| **2** | ✗ |

**13 张不准确。**

### 2.2 关键：这枚标签是**事后诊断**，不是引导

瑞思核实、我确认：它在 `) : (` 分支内（答题前的猜句界面走的是 `!revealed` 分支）——**揭示之后才出现**。

所以它**没有「引导作用」可以豁免精确性**：诊断文案说错就是缺陷。

### 2.3 修法

改为 **「整句都要看」**——「缺了一块」⊂「整句都要看」，**放宽是安全的（缩小才必须正确）**，对 52/52 都成立。零术语、不触发既有红线。

## 6. 方法学教训

1. **「生成病句」比「显示错字」严重**。上批修的是 UI 标签说错（用户看一眼就过），本批修的是**病句进错词本**（用户会看到并记住）。**同一类缺陷的影响面差异很大，要先量化再排优先级。**
2. **改数据会引出连锁缺陷**。我改 13 处文案后，`pickCorrectionWord` 立刻开始返回中文虚词「把」——**任何数据改写都要重跑全部下游消费者**。
3. **补文档时我犯了低级错误**（重复字段声明导致 77 处测试失败）。**文档改动不是「无风险改动」**——它也是代码，也要跑 tsc 与测试。
4. **`startsWith("去掉")` 被当成了语义定义**。这是「用字面判断替代语义判断」的典型——与项目此前 5 次审计口径缺陷同源。
