## 0. 一个重要的前置事实：方案已是现状

走查代码后确认：**两份 UX 方案的主体已经落地**。

- 入口页已是重设计后的形态：继续阅读 Hero 卡（`AdventurePage.tsx:282-303`）、主题卡场景插画、难度分段控件（`:367-380`）、灵感 chips（`:397-410`）、ConfirmDialog 删除（`:547-556`）、随机推荐（`:157-167`）。
- 阅读页已是一屏化形态：顶栏合并 + 摘要气泡（`AdventurePlayPage.tsx:1022-1151`）、正文内部滚动容器（`:1155`）、底部动作坞（`:1223-1237`）、生词星标 + 抽屉（`:1140-1149, :1247-1270`）、字号三档（`:1079-1107`）、回看/重选确认弹层（`:1272-1291`）。

因此 ADVENTURE_UX_PLAN 的 P1–P8 不应再当作"待解决问题清单"，而应当作"已修复项 + 残留项"来核对。本报告第 3 节的痛点排序基于**代码现状**重新诊断。

## 1. 用户画像与动机结构

### 1.1 画像

| 维度 | 描述 |
|---|---|
| 身份 | 成人、英语零基础或接近零基础（A1–A2 起步），自用工具的唯一用户 |
| 场景 | 桌面端（Tauri），一次坐下来 8–15 分钟，无人打扰的私人时间 |
| 英语水平 | 读句子需要译文兜底；听到弱读连读会丢词；写作几乎零产出 |
| 心理特征 | **没有"我要学好英语"的目标感**（GRAMMAR_ADVENTURE_PLAN §0：有目标感的人不会零基础）；对"被纠正"敏感，要的是**体面地学会，不是被哄**；反感低幼化 |

### 1.2 动机结构（为什么打开冒险，而不是打开听写）

产品内三条主线的动机差异：

| 模块 | 动机类型 | 驱动力 |
|---|---|---|
| 听写/复习 | 工具动机 | "今天该练了"——靠自律，易断 |
| 单词卡 | 积累动机 | 缺口闭合（复习队列清零） |
| **冒险** | **叙事动机** | "后来呢？"——悬念 + 收集 + 被看见 |

冒险模块在产品里的独特价值，是它是**唯一一个"有东西在等你"的模块**（GRAMMAR_ADVENTURE_PLAN §0 对 V1 的批评恰恰是没有东西等用户）。其动机结构对应六个真机制中的四个已经成立：

- **④ 悬念**：章节在分支处停下，想知道后面 → 已成立，但只做了一半（见痛点 H6）
- **② 收集**：生词进"冒险积累"词库 → 已成立
- **③ 成长可见**：路线卡的"第 N 章 · N 个生词" → 已成立但度量粗糙（痛点 H4）
- **⑥ 安全混乱**：自定义行动输入框是雏形，但离线模式下是"假自由"（痛点 H5）

尚未成立的：**① 即时因果**（点选项不等于"我说的话改变了世界"——这正是语法冒险 V2 语言之门要补的）和 **⑤ 角色关系**（无 NPC 记忆）。

## 2. 端到端用户旅程地图

### 阶段一：首次进入 `/adventure`

| 项 | 内容 |
|---|---|
| 用户目标 | 搞懂"冒险学习"是什么、30 秒内开始第一段 |
| 关键动作 | 扫视 Hero → 看主题卡 → 选难度 → 点开始 |
| 触点 | Hero 文案"读一段故事，做一次选择，把真正想记住的词收进词库"（`AdventurePage.tsx:278`）；4 张模板卡 + 自定义卡；A1–C1 分段控件 |
| 痛点 | ① 首次进入无进行中冒险时，Hero 区只剩一句文案，页面教学成本压在这一行上——"做一次选择"具体长什么样，要点进去才知道；② 默认难度 A2（`:111`），对真零基础偏高，且无"不确定就选这个"的引导；③ 自定义卡的"需配置 AI"徽章（`:359`）提前暴露了依赖，好设计，但首次用户可能根本不知道设置在哪——好在有"去设置"链接（`:416`），仅自定义模式展开时才出现 |
| 机会点 | 首次进入时默认选中并微高亮"推荐起点"（A1 + 一个模板），把决策数从 3 个降到 1 个 |

### 阶段二：创建冒险

| 项 | 内容 |
|---|---|
| 用户目标 | 用最少思考生成一个"想读下去"的第一章 |
| 关键动作 | 模板模式：直接点开始；自定义/推荐卡模式：写线索 → 等 AI 生成首章 |
| 触点 | 主题卡（radiogroup 语义）、灵感 chips、AI 说明条、开始/生成按钮 |
| 痛点 | ① **P5 残留（新形态）**：选中"随机推荐"的 AI 卡后，线索输入框和灵感 chips 仍然显示（`:397` 只排除 custom 模式），但 `startAdventure` 会**用推荐主题直接覆盖用户写的线索**（`:179-183`）——用户填了"我想找一只走失的猫"，生成出来的故事和猫无关，且无任何提示。这是整个入口页现存最真实的"被欺骗感"时刻；② **P8 残留**：AI 生成首章期间只有按钮文案变为"AI 正在构思"（`:428`），无骨架屏、无进度感，10 秒以上的等待里用户不确定是否卡死；③ 生成失败只有表单底部一行 `adv-error`（`:419`） |
| 机会点 | 选中推荐卡时隐藏线索框或明示"线索将被忽略"；生成中加氛围文案轮播 + 可取消 |

### 阶段三：阅读与选择（核心循环的"读 → 选"）

| 项 | 内容 |
|---|---|
| 用户目标 | 读懂这一章（生词可点、译文可看、可听），然后做一个"我的选择"推进故事 |
| 关键动作 | 逐句点译文 / 切对照模式 → 点词查释义 → 播放句子或整章 → 读到底部动作坞 → 点选项或写自定义行动 |
| 触点 | 顶栏（进度/模式/播放/字号/生词入口）、正文容器、词典 popover、动作坞、路线图右栏 |
| 痛点 | ① **离线+无 AI 用户读不透**：历史/离线章节若无逐句译文，"生成译文"按钮直接报"请先在设置中配置 AI"（`AdventurePlayPage.tsx:661-664, :1163-1168`）。对一个 A1 用户，**译文是"读"这个核心动作的地基**，而它被绑在 AI 配置上；② **自动预加载阻塞选择**：预加载进行中所有选项按钮和自定义行动全部 disabled（`:1232, :1235`），用户读完正兴奋时被迫等转圈——核心循环"读→选"在最爽的点上被掐断；③ **自定义行动的"假自由"**：无 AI / AI 失败回退离线时，用户写的行动被静默丢弃，故事走预置分支（`:909-916`），状态行只说一句"已使用离线剧情续章"。用户会隐约觉得"我写的没用"，但说不清为什么——这比直接告诉他"离线模式不支持自由行动"更伤信任；④ 选择期间 `isContinuing` 时也无骨架，只有 status 行小字 |
| 机会点 | 预加载改为逐选项解锁、允许点击打断；离线模式下隐藏或改写自定义行动输入（"离线剧情沿着预设路线走"）；译文与 AI 解耦（内置词典级整句机翻兜底或预置离线译文包） |

### 阶段四：收词

| 项 | 内容 |
|---|---|
| 用户目标 | 把"想记住的词"收进自己的词库，且感到"我收获了东西" |
| 关键动作 | 路径 A：正文点词 → popover 里点星标收藏（即时）；路径 B：顶栏星标打开抽屉 → 勾选 → 保存所选词汇 |
| 触点 | 词典 popover 星标（`:1310-1322`）、顶栏生词徽章（`:1148`）、生词抽屉（`:1247-1270`） |
| 痛点 | ① **保存反馈太轻**：保存成功后抽屉关闭，反馈只是动作坞底部一行 status 小字"已加入 N 个词"（`:989, :1236`）——核心循环里最有成就感的一环，反馈强度却是全页最低的；② 两条收词路径的产出物不完全一致（popover 收藏直接进"冒险积累"，抽屉保存走 `saveAdventureVocabulary`），用户无从感知它们去了同一个地方；③ 抽屉徽章数字只在有待收词时出现，收完后星标变成"无状态"，缺少"本章已收 5 个"的正向展示 |
| 机会点 | 保存后给一个 1.5 秒的轻量收束动效（词卡飞向星标 + "冒险积累 +N"）；星标常显本章已收数 |

### 阶段五：离开

| 项 | 内容 |
|---|---|
| 用户目标 | 随时走，不担心丢失进度 |
| 关键动作 | 点返回 / 直接关 App |
| 触点 | 顶栏返回按钮；自动存档（业务层） |
| 痛点 | ① **离开时刻没有任何"钩子"**：章节读完、词收完，界面就此静止——没有"下一章会发生什么"的一句话预告。GRAMMAR_ADVENTURE_PLAN §5 明确把"每关结束的悬念预告"列为回访钩子，现状完全没有；② 句级阅读进度（`lastReadSentenceIndex`）不持久，下次进来从章头重读——短章无所谓，长章对照模式下要重新找位置 |
| 机会点 | 章末（最后一个节点选择后）生成一句悬念预告，存进节点，供入口页 Hero 卡展示 |

### 阶段六：回访续读

| 项 | 内容 |
|---|---|
| 用户目标 | 3 秒内回到上次的故事现场 |
| 关键动作 | 打开 `/adventure` → 看 Hero 继续卡 → 点"继续阅读" |
| 触点 | Hero 继续卡（`AdventurePage.tsx:282-303`）：插画 + 难度徽章 + 进度条 + "第 N 章 · 收了 N 个词 · X 天前保存" |
| 痛点 | ① **进度条语义模糊**：`percent = path.length * 20`（`:141`），AI 冒险没有终点，"20%、40%"暗示一个并不存在的总长度——第 5 章就 100% 了，之后进度条失去意义；② Hero 卡只回答"我读到哪"，不回答"**故事里正发生什么**"——没有悬念钩子，回访动机全靠用户自己的记性；③ 多条进行中路线时其余路线在横向 scroller 里只露 6 条（`:450-451`），更多要点开弹层，低频可接受 |
| 机会点 | 进度条改为"已读章数"等诚实度量 + 悬念预告文案；Hero 卡加一句"上次：……"的剧情残片 |

### 3.2 合并重排（按对核心循环「读 → 选 → 收词 → 回访」的伤害）

| 排序 | 痛点 | 击中的循环环节 | 来源 | 理由 |
|---|---|---|---|---|
| **H1** | 无 AI 时历史/离线章节拿不到逐句译文 | **读（地基）** | `AdventurePlayPage.tsx:661-664, :1163-1168` | 译文是 A1 用户"读"的前提。它一断，核心循环第一步就不成立，后面全部免谈。伤害面是"无 AI 配置的全部会话"，而目标用户恰恰最可能不配 AI |
| **H2** | 自动预加载期间选项整体禁用 | **选（峰值时刻）** | `:1232, :1235` | 读完正文、动机最高的瞬间被迫等待。这是把"爽点"变"堵点"，直接打断心流。比 H1 排名低只因为它只在开了自动预加载时发生 |
| **H3** | 自定义行动在离线回退时被静默丢弃 | **选（信任）** | `:909-916` | "我写的没用"的隐性感知侵蚀的是用户对"选择有意义"的信仰——而"选择有意义"是冒险区别于普通阅读的整个卖点。GRAMMAR_ADVENTURE_PLAN 的即时因果机制也建立在这上面 |
| **H4** | 收词保存反馈过轻 + 进度度量失真 | **收词 / 回访** | `:989, :1236`；`AdventurePage.tsx:141` | 收词是循环里唯一的"获得"，反馈强度与情感价值严重不匹配；进度条 5 章即 100% 失真，削弱"路线是资产"的感知 |
| **H5** | 无悬念回访钩子 + 句级进度不持久 | **回访** | 章末无预告；`:338` 初始 -1 | 回访是循环闭环的最后一环。自用产品没有推送、没有 streak，悬念是唯一合法的回访驱动，目前完全缺位 |
| **H6** | P5 残留：AI 推荐卡静默覆盖线索 | 创建（首次体验） | `AdventurePage.tsx:179-183` | 只影响"填了线索又选推荐卡"的交集场景，频次低，但一旦发生就是"产品没听我说话"的首次印象 |
| **H7** | P8 残留：AI 生成中/失败反馈弱 | 创建 / 续章 | `:428, :419`；`AdventurePlayPage.tsx` status 行 | 等待焦虑，可通过氛围文案和骨架缓解，不致循环断裂 |

排序逻辑一句话：**先保证"读得懂"，再保证"选得动、选了有用"，然后让"收获被看见"，最后修"想回来"**。前三个不修，核心循环是漏的；后四个决定循环转得久不久。

## 4. 用户感知视角的竞品感受（一小节）

成人初学者用多邻国 / LingQ 类产品时的典型摩擦，从"坐在屏幕前的那个人"的视角看：

**多邻国**：前三天是甜的——绿猫头鹰、连击、即时反馈。第一周之后，streak 从激励变成债务："我不是想学，我是怕断。"对成人初学者更深的摩擦是**低幼化的体面损耗**（卡通音效、夸张表扬）和**学用脱节**——刷了 200 天，依然说不出一句完整的话，因为全程在点选项，零自由产出。GRAMMAR_ADVENTURE_PLAN §1 的反例清单（签到、排行榜、经验条）几乎就是多邻国机制清单的反面。

**LingQ**：内容驱动、阅读中收词的思路与本产品最接近，但成人初学者的实际体验是**工具感压过故事感**：满屏高亮词（蓝/黄/熟）让页面像待办清单而不是故事；收词动作（造 LingQ）高频打断阅读；没有角色、没有悬念，"今天读这个"的理由永远来自自律。它的 friction 不是焦虑而是**孤独**——没有东西记得你、等你。

**本产品的差异化位置**（用户感知层面）：不多邻国式的"逼你回来"，也不 LingQ 式的"给你工具自己扛"。冒险模块已有的"温和奇幻 + 无惩罚 + 收词直达个人词库"是稀缺组合。缺口在：故事还**不认识它的读者**（无 NPC 记忆、无悬念预告）——这正是 V2 语言之门和 NPC 记忆要补的，方向上完全正确。

## 5. UX 机会建议（5 条）

| # | 建议 | 对应旅程阶段 / 痛点 | 做法要点 | 预期改善的指标 |
|---|---|---|---|---|
| O1 | **译文与 AI 解耦**：离线模板章节预置逐句译文；AI 章节生成时同步产出译文并随节点持久化，历史缺译文章节给"词典级整句兜底"或明确的一键补齐入口 | 阅读（H1） | 离线包直接带 `sentenceTranslations`；AI 续章契约里已可要求译文，落库后历史章节不再缺 | 章节阅读完成率 ↑；对照模式开启率 ↑；"译文生成失败"状态出现率 → 趋近 0 |
| O2 | **预加载不阻塞选择**：选项逐个就绪逐个解锁；预加载中允许点击（打断预加载直接走实时生成） | 选择（H2） | 把 `preloadingChoiceIds.size > 0` 的全局禁用改为按选项粒度禁用 + 点击中断逻辑 | 读完→点击的间隔时长 ↓；章节推进率（读完章节点选项比例）↑ |
| O3 | **自定义行动诚实化**：离线/回退场景下输入框改占位文案明示"离线剧情沿预设路线走"，或回退时把用户行动回显为"小灯没听懂，先跟着故事走"式剧情化回应 | 选择（H3） | 最小版：回退时 status 点名"你写的『……』这次没能用上"；进阶版接入 V2 误读支线机制 | 自定义行动使用率（目前被静默丢弃，无感知）变得可测量；续章后离开率 ↓ |
| O4 | **收词反馈仪式化 + 星标常显已收数**：保存后词卡飞入星标的 1.5s 轻动效 + toast"冒险积累 +N"；顶栏星标常显"本章已收 N" | 收词（H4） | 复用现有 vocab 抽屉与 status 通道，加一个短暂庆祝态；不动业务逻辑 | 每章收词保存率 ↑；收词→词库复习的转化 ↑（用户对"冒险积累"词书的存在感增强） |
| O5 | **悬念回访钩子**：章末由 AI（或模板预置）生成一句"下章预告"存进节点；入口页 Hero 卡展示"上次：……（预告/最后一句）"；进度条改为诚实的"已读 N 章" | 回访（H5） | 数据上给 `AdventureNode` 加一个可选字段；展示上改 Hero 卡副文案；度量上弃用 `path.length * 20` | D1/D7 回访率（自用语境：连续使用天数）↑；Hero 卡点击率 ↑；回访后停留时长 ↑ |

优先级建议：O1、O2 先做（修循环的"漏"），O5 第三（修循环的"回流"），O3/O4 可与语法冒险 V2 的语言之门合并实施，避免重复改动动作坞。
