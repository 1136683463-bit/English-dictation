## 📌 TL;DR（执行摘要）

- **核心目标**：设置板块当前最大的问题是「信任缺口」——改动不保存即丢、恢复/云还原无预览全量覆盖、云同步成功却仍误报"未备份"。本 PRD 以"可靠性底线 → 易用性 → 数据所有权叙事"三层推进。
- **关键决策**：采用全竞品一致的「即改即存」自动保存模型，消灭页面级+AI 面板双轨保存；云同步假阳性 bug（S 工作量、高信任收益）最先修；AI 配置模板化降 P1 避免与保存模型改动同批叠加回归面。
- **排期**：1 人兼职（8-10h/周）共 7 周 3 个迭代：信任与地基（W1-2）→ 安全网与首次体验（W3-4）→ 面板整合收尾（W5-7）。
- **下一步**：产品负责人拍板 5 个待确认问题（见文末），冻结需求池后进入迭代 1。

## 1. 产品目标（3 个正交目标）

- **G1 消灭设置丢失与误覆盖类事故**：统一保存模型，消除"改了没保存即丢"与"恢复/同步无确认全量覆盖"两类不可逆事故；三个月内相关事故为 0。
- **G2 让非技术用户 5 分钟完成首次配置**：首次启动引导 + 档位化推荐值 + AI 预设模板，首次配置完成率 ≥ 80%，平均耗时 ≤ 5 分钟。
- **G3 把数据所有权做成一级叙事**：以"数据保险箱"面板整合导出/恢复/重置/备份状态/同步健康，备份及时率 ≥ 90%。

三个目标正交：G1 是可靠性底线，G2 是易用性，G3 是信任叙事。

## 2. 用户故事

- **US1 日常微调（自主学习者）**：小李调每日新词从 20 到 10，改完直接切走，期望立即生效且看到"预计完成天数"变化，不需要找保存按钮。
- **US2 首次配置（家长）**：王妈妈首次给孩子装应用，跟随三步引导：试听调语速→选择目标档位（轻松/标准/强化）→看到备份入口，5 分钟内完成，不接触 Base URL、令牌等开发者词汇。
- **US3 换设备迁移**：老周在新电脑恢复云端数据，恢复前看到"将覆盖本地 N 条生词/M 次复习记录（最后同步于 X）"预览并二次确认，不会静默回滚。
- **US4 误操作恢复**：小赵误点"恢复 JSON"选错文件，由于有预览+确认弹窗，在点击"确认覆盖"前取消，数据无损。
- **US5 语音故障排查**：小陈发现试听没声音，点击"诊断"看到是系统无可用英语声音，按指引安装后恢复，而不是看到一行报错就卡住。

## 4. 竞品对比（竞析）

对比 Anki / 墨墨背单词 / 百词斩 / 不背单词 / Duolingo（官网与官方手册核实为主）：

| 维度 | 我方 | 竞品现状 |
|---|---|---|
| 保存模型 | 页面级保存+AI 独立保存（双轨） | **全部即时生效，无保存按钮** |
| 学习目标配置 | 裸数字输入 | Duolingo 四档档位化；百词斩滑块+预计天数 |
| 改动副作用提示 | 无 | 不背单词"改词量将重启学习组"弹窗 |
| 防呆 | 二次点击确认 | Anki 展示影响范围（"用于 N 个牌组"） |
| 备份/导出 | JSON/Anki CSV/MD + 恢复（**显著强于全部竞品**） | 除 Anki 外均弱 |
| 同步 | 自建服务器+令牌 | AnkiWeb / 账号云 |

可借鉴模式：①Duolingo 目标档位化+自定义兜底；②百词斩目标→效果联动预览；③不背单词副作用前置提示；④Anki preset 方案机制；⑤Anki 超限软劝导；⑥Anki 展示影响范围式防呆；⑦全竞品即时生效。

差异化机会：数据所有权是一级叙事（竞品结构性无法跟进）；AI 连接测试推广为统一健康检查；自建同步透明化（上次同步时间+本地/云端数据量对比）。

## 5. 数据依据（数析）

- **三大每日目标是软指标**：dailyNewWords/dailyReviewLimit/dailySentences 只驱动进度环、周报目标与完成天数预估（reviewService.ts:78-88、statsService.ts:141-143），不截断学习队列（队列上限在 ReviewPage.tsx:81 默认 999）。改错不破坏闭环，但约束力弱。
- **高危关键路径**：strictPunctuation 改变判分→错词→复习调度全链；speech 三项被 6+ 处消费（SpeakButton/SpellingPage/AdventurePlayPage 等）。
- **aiProvider 是孤岛型总开关**：默认关闭，未配置时 AI 功能全部本地降级。
- **同步是"最后写入赢"**：按 savedAt 整库覆盖（syncService.ts:76-80），无字段级合并。
- **假阳性 bug（P0 级）**：云同步成功不回写 lastExportedAt，开了云同步的用户仍被提醒"7 天未备份"（storage.ts:1016 + markDataExported）。
- **默认值双源重复定义**：storage.ts:50-75 与 testUtils.ts:6-31，改默认值需同步两处。
- **无埋点现状**：仅 grammarTelemetry.ts 有本地事件，设置页零埋点。

## 7. 关键流程描述

**F1 统一保存模型**：用户修改任意字段 → onChange 更新 React state → 500ms debounce 写入 storage（原子单 key）→ 页头状态区显示"已自动保存 · HH:mm"→ 写入失败状态区变红并重试；切页/关窗前 flush。AI 配置同此链路，测试连接为只读操作不触发保存。

**F2 恢复前预览确认**：选择"恢复 JSON/云端恢复"→ 读取源数据计算 dataScope（生词 N/复习 M/句子 K/最后保存时间）→ 弹窗对比本地与源数据 → 点击"确认覆盖"→ 执行全量覆盖 → 完成提示。首版不做撤销快照（成本 M→L，列入 R08 后续增强）。

**F3 首次启动引导**：检测无配置标记 → 步骤1 试听（示例句，可调语速/口音）→ 步骤2 目标档位（默认标准，展示预计每日投入）→ 步骤3 备份说明（数据归属+引导首次导出或配置云同步）→ 写完成标记 → 进首页。任一步可跳过。

## 8. Non-goals（明确不做什么）

- 不做账号体系与多端在线协同（云同步保持自建服务器+令牌模式）。
- 不做字段级同步合并，保持"最后写入赢"，仅以预览+确认降低风险。
- 不改语音引擎选型（仍用系统 TTS）。
- 不改听写判分算法；strictPunctuation 等高危链路仅在设置侧加影响说明文案。
- 不做埋点的后端上报，沿用 grammarTelemetry 本地模式（localStorage 环形缓冲+用户主动导出）。
- R02 首版不做"撤销到覆盖前快照"。

## 9. 时间线 & 里程碑（路径）

**前提**：1 人兼职开发，8-10h/周，共 7 周；M 级需求实际约 1.5-2 周/个，已按此校准。

**迭代 1（W1-2）：信任与地基**
- R03（W1 前半先行修复止血）→ R13 → R01（含本地埋点埋设）
- 依赖：R01 依赖 R13 的默认值单一来源
- **M1（W2 末）**：全设置即改即存上线；埋点开始记录保存成功率与导出频次
- 验证：17 个 updateData 调用页面冒烟走查（重点：导入、拼写、语法页写入后刷新不丢）

**迭代 2（W3-4）：安全网与首次体验**
- R02（复用 R01 埋点管道）→ R06
- 依赖：R06 引导的目标档位步骤依赖 R05 的档位定义——**档位枚举与文案作为 R05 先行交付物在本迭代定稿**（实现放迭代 3）
- **M2（W4 末）**：三大危险操作均有预览弹窗；新手首启完成率可度量
- 验证：恢复 JSON → 取消/确认 → 重置完整链路演练

**迭代 3（W5-7）：面板整合与体验收尾**
- R05 → R08（合并 R02 弹窗入口）→ R04 → R07 → 视余量从 R09/R11 挑一个 S
- **M3（W7 末）**：设置页收敛为"目标 / 语音 / AI / 数据保险箱"四区块；R10/R12 视进度入下季度 backlog

**排期风险**：
1. R01 回归面全项目级（约 70 处 updateData 调用），debounce 期间丢数据是最大隐患 → 卸载前 flush + 冒烟清单全覆盖。
2. R02 撤销快照成本不可控 → 首版剔除，列 R08 后续增强。
3. R05/R06 跨迭代耦合 → 档位枚举作为接口在 PRD 显式标注（已标注）。
4. 单人节奏波动 → R04/R07 为首选缓冲项，可整体滑入下季度不阻塞主线。
5. 无专职 QA → 冒烟 checklist 存仓库，迭代 1 开始积累。
