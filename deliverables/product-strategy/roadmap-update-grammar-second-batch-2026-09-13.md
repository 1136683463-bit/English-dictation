  1. D1 放行条件是否全部收口（收口 → D1 正式关闭）；

- **止损触发器（验证期全程生效，来自 D1 裁决）**：
  - 首玩有效认知时长中位数 **<4.5min（270s）** → D1 回落止损档：保留折叠卡主线，暂停模板大改，重估方向；

  - output 无提示首题通过率 >70% 或 =0 → 意图锚/阶梯提示参数重校。

- **风险提示**：n=1 单人样本置信度有限已写入判据；三项风险（§4）均有缓解动作，无需追加资源。

### 3.2 工程版（技术细节 / 时序 / 依赖）

- **时序**：E2 接线验证是 E4 上线的硬前置——`sectionBreakdown` 字段、R22 双发修复发布版本、`hunt_case_settled` 埋点、破段入完课主流程四项必须在上线前逐项书面确认（D1 裁决行动 #1/#2）。
- **上线纪律**：**验证窗口内所有试玩/使用必须走打包版或关闭 vite dev server HMR**——durationMs 截断（−321s / −384s 实锤）的根因就是开发会话热重载；E5 数据若混入 HMR 会话即作废重采。
- **兼容**：第二批遵循「不新增 schema 必填字段、零迁移」；不改动既有 20 课数据与六段模板结构。
- **依赖**：huntCaseIds 多案挂载已验证（L10/L11/L13/L20）；L24 双核心句需确认 targetSentence 单句字段无渲染假设。
- **回传**：E5 结束后由数析出绑定验证报告，工程侧只需响应指标异常排查请求。

### 3.3 内容教研版（生产要点 / 红线 / 优先级）

- **生产范围**：L21–L24 六段数据全量新产（不复用旧四段），严格按 PRD §2 逐课要点；分词负担硬约束 = 每课 2 个不规则形（done/eaten → been/seen → broken/written），L24 零新增。
- **红线（守卫级 checklist，任何一条不过即打回）**：
  - guided 恰 4 题（1 choose + 2 arrange + 1 spot）；practice ≥4 题，第 4 题与 variants 否定/疑问变体**逐字一致**；distractors 整词不与答案词重复；
  - recall 必含 intentZh 四字段；每课跨课复现题 ≥1；
  - 深度 6 字段全量；对比卡 wrong 必须真错；话术**零术语**（「做过版」「昨天版」「信号灯」），超纲词 0–3 且带注释位；
  - 5 个新案：新错 1–2 + 旧错 1–2、单 token 可修、零枚举扩展、标 `reviewed: true`。
- **两个内容级重点**：① **L21 一词两义**（have = 有 vs have + 做过版）必须在主线对比卡正面拆解，不能塞折叠卡（PRD §1.4）；② **L21 recall 降档**忆 L10 旧句，L22 起恢复考新句——这是对 recall 首玩 0/3 的直接缓解。
- **优先级**：E1（9/14–9/17）为当前唯一 P0；封面图（E3）与数据生产可部分并行。
