## 2. 用户反馈摘要（来自瑞思）

> 原话（2026-09-12）：「这些课程，流程都太短了，而且说的太浅显，初学者未必能学懂。」

**三种体验缺失**：①讲解浅显 → 确证感缺失（R05 完课确证仪式、P2 母语定制解释/FAQ 卡对位）；②流程太短 → 无掌握闭环（R03/R04 输出与复习对位）；③学了不复 → 无复习回路（R03 SM-2 产出型复习卡对位）。

**5 风险对路线图节奏的约束**（直接写进主线设计）：
- 加深=变长吓退 → **主线锁 6–10 分钟**，讲解加深走侧栏/展开层而非拉长主流程，M1 就验证展开率 ≥50%；
- 术语伤害 → P2 母语定制解释（R10）排后，先用 M1 数据确认术语是否真是卡点；
- 错句被当示范记住 → R07 对比卡「先判断再揭示」锁进 M2，不可推迟到 M3；
- 复习变负担 → 复习卡硬上限 ≤10 张/≤5 分钟、最旧错题优先截断，写进 R03 验收标准；
- 课内节奏断裂 → 内容扩量（R06）新元素归段内固定位置，排 M2 闭环验证之后。

## 3. 竞品动态（来自竞析）

**动向**：多邻国 Explain My Answer 已免费化——**单次讲解即将成为行业基线**；扇贝词文串学已跑通「词汇→文本」串联；开源 GrammarLab 快速逼近闭环形态。

**对节奏的含义**：单次讲解免费化意味着「讲得更透」本身不是护城河，**护城河在「错句→归因→复习→验证」的闭环**（无直接竞品）+ 中文负迁移库 + 语法点级 SRS。因此节奏上**闭环（M1/M2）绝对优先于内容增强（M3）**：R10/R11（讲解增强类）即使数据达标也排在 R12–R15 之后考虑；R07（对比卡先判断再揭示）提前锁 M2，与「错句示范」风险共同构成差异化闭环的质量底线。

### 4.2 依赖关系说明

- **R01 是一切指标的前提**：无埋点则无基线、无决策门，故置于第 1 周第 1–2 天，先于所有功能。
- **R03 依赖 R01 + diffService tag 扩展**：错句回收需 diffService 输出可按语法点标记的 tag；tag 口径须与 R09 的 DiaryIssue 枚举一次性对齐（见待确认问题④），避免返工。
- **R08 依赖 R01 + R03 数据积累 ≥1 周**：频率×新近加权需要至少一周的复习行为数据，故排 M2 中后段。
- **R02 是 R03/R04 的输入**：前测错题即复习卡首批素材（处理建议见待确认①）。
- **P2 全部凭 M1/M2 决策门裁决**：R10–R15 不做预告承诺。

### 4.3 决策门设计

**M1 门（第 1 周末，决定 M2 取舍）**
- **继续**：practice 完成率≥90% 且 无提示首次通过率≥80% 且 展开率≥50% → M2 全量四项按计划。
- **调整**：某一项在 80–90% 区间 → M2 优先修该项，R08 周报顺延为 M2 末交付。
- **止损**：practice 完成率<80% → 暂停 M2 全部新功能，先做主流程可用性排查（大概率是 6–10 分钟主线被破坏），修复后重开 M1 复测一周。

**M2 门（第 2 周末，裁决 P2 做哪几项）**
- **继续**：错句回收率≥70% 且 复发率<30% 且 次日复习≥50% → 按 P2 优先序裁决：
  - 展开率≥50% 但用户停留浅 → 做 R10/R11（讲解增强）；
  - 时态类错误占比 Top2 → 做 R12 矩阵可视化；
  - 复发率偏高且集中在高频错型 → 做 R14 预告 + R13 音频；
  - 复习习惯已稳定 → 做 R15 can-do 徽记强化动机。
- **调整**：回收率 50–70% → P2 只做与回收率直接相关的项（R07 补强/R14），其余推迟。
- **止损**：次日复习<30% → P2 整体冻结一周，先解决复习负担问题（降卡量、调提醒），确认 SRS 假设成立后再谈增强。

**M3 门（第 4 周末，收官）**：对照北极星首次读数（目标：向 ≥25 句/周爬坡的趋势确认），输出下一季路线图草案。

## 5. 利益相关者沟通要点

### 产品负责人视角（用户本人）
- **为什么先做闭环不做内容**：单次讲解已成行业基线，讲得更透不构成差异化；错句→归因→复习→验证闭环无直接竞品，且只有闭环能回答「学了是否真会」。
- **预期体验变化**：前测定位薄弱点 → 每课错题自动变成复习卡（≤5分钟）→ 完课有确证仪式 → 每周一份 Top3 弱点周报。体验上不是「课变多了」，而是「学了不会忘」。
- **如何判断成功**：第 2 周末看四数——次日复习≥50%、错句回收≥70%、复发率<30%、无提示首次通过≥80%；长期看每周有效输出句数向 25 爬坡。

### 开发视角
- **实施顺序**：R01（第1–2天）→ R02 → R03 → R04 → R05（第1周）；R07 与 R06 可并行（第2周前半），R08、R09 收尾。
- **每步验收标准**：R01=5 项埋点数据可回放；R02=前测错题直接可入复习队列；R03=卡量上限与截断逻辑生效；R04=无提示模式独立可开；R05=小结展开率可统计；R06=变体≥3/案件≥20/fragment≥3；R07=揭示前有判断步；R08=周报含 Top3；R09=AI 不可用时降级路径可用。
- **最容易返工的点**：① DiaryIssue 枚举与 huntService tag 对齐——建议第 1 周设计 R03 时就冻结 tag 词表（对应待确认④）；② SM-2 扩展兼容性——复习卡字段设计须兼容既有 reviewService 数据，先迁移验证再切量。

### 内容教研视角
- **质量红线**：单条讲解 ≤500 词、口语化、术语首次出现必须给中文白话；混题占比 30–50%（纯新题不超半，复习穿插不欠）；扩量错句必须带「错在哪+正确版」解释，杜绝裸错句。
- **AI 初稿+人工校验流程建议**（对应待确认③）：AI 按模板生成变体/案件初稿（含错误设计+解析）→ 人工按红线逐条校验（错误是否自然、解析是否准确、500词/混题比是否达标）→ 抽检通过率 <80% 则该批全部人工重写。校验工时计入 R06 的 2 人日内。
