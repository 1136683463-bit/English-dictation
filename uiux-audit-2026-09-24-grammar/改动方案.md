## 4. 改动四：`ned` 干扰项  ✅ 已完成 2026-09-24（作废了本节的「不要打补丁」结论，见 4.4）

### 4.1 成因（已实测确认，与本节最初版本不同）

**不是**「`need` 加 `d`」，而是**词干还原把 `need` 误当过去式剥掉了 `-ed`**：

```ts
const base = lower
  .replace(/ies$/, "y")   // "need" 不匹配
  .replace(/ing$/, "")    // 不匹配
  .replace(/ed$/, "")     // ← "need" 以 "ed" 结尾 → 被剥成 "ne"
  .replace(/s$/, "");     // 不匹配
// base = "ne"
if (/[^aeiou]y$/.test(base)) ...            // 否
else if (/e$/.test(base)) push(`${base}d`); // "ne" 以 e 结尾 → push("ned")
```

根子在于 **`-ed` 剥离无法区分「本身以 -ed 结尾的基础形」与「过去式 -ed 形」**：
`need → ne`、`seed → se`、`speed → spe`，之后 `-e` 分支各自产出 `ned` / `sed` / `sped`。

### 4.2 为什么不该打第四个补丁（两个候选修法都实测失败）

**修法甲：只拦 `-ed` 剥离这一步（剥完不是真词就不剥）。** 逐步比对全表：

| 词 | 现状产出 | 修法甲产出 | 判定 |
|---|---|---|---|
| `need` | **`ned`** | `needs / needed / needing` | 修好 |
| `seed` / `speed` | `sed` / `sped` | `seeds / seeded`、`speeds / speeded` | 修好 |
| `liked` | `liks / liked / liking` | `likeds / likeded / likeding` | 新旧都含非词 |
| `lived` / `closed` / `studied` | `livs…` / `clos…` / `studis…` | `liveds…` / `closeds…` / `studieds…` | **改完全是非词，旧版至少混着真词** |
| `watches` | `watched` ✓ | `watchs / watched / watching` | **引入新非词** |
| `needs` / `cleaned` / `walked` / `wanted` / `plays` / `takes` | 正确 | 正确 | 无变化 |

即：修好 3 个、弄差 4 个、新增 1 个。**这是第四次打补丁，而且是负收益的那种。**

**修法乙：对 morph 产物做统一真词校验。** 需要一个能判断「是不是英语词」的词表，项目现有的都不行：

- `bundledDictionary`（12000 词条）：有 `cleaning`，**没有** `cleaned` / `needs` / `needed` / `wanted` / `walks` / `helps` —— 用它过滤会把合法的 `-s` / `-ed` 干扰项整批砍掉。
- `courseVocabulary()`：只是课程英文文本里**出现过**的词，而 morph 分支存在的意义正是**生成**文本里没出现的形态，用它过滤等于取消这个分支。
- `KNOWN_VERBS`：里面**同时**有基础形和变形（`need` / `needs` / `needed` 三个都在），所以 `has()` 无法区分「这是基础形」还是「这是变形」——这正是这个 bug 反复复发的根本原因。

### 4.3 当时的结论与建议（已被 4.4 推翻）

**代码侧的建议：不要动。** 理由：

1. 规模是 **1 道题**（全库 369 个去重干扰项里只有 `ned` 一个非词，见 §4.1 的扫描）。
2. 两个显而易见的修法都会引入新的非词或砍掉合法干扰项（§4.2 实测）。
3. `liked` / `lived` / `closed` / `studied` 这 4 类**已经**在产出非词（`liks` / `livs` / `clos` / `studis`），
   只是被 `candidates.slice(0, 3)` 挡在选项之外、从未浮出。**这个函数需要的是带形态规则的重写
   （或一份含变形形式的词表），不是补丁**——而那次重写的价值，取决于是否还有别的非词会浮出。

**真正该做的一步：把检查扩大，而不是把生成改窄。**
项目自己的 `fabricatedDistractor` 检查只报了 1 例，但它覆盖的词形有限——
建议按 `tools/gq2-morph-scan.probe.mts` 的做法（扫全部 369 个去重干扰项、逐个判断是否英语词）
扩成常规检查。**先确认这一类的真实存量**，再决定要不要做那次重写。

## 8. 复习卡生成题（GQ1）：单词语卡类缺陷整批归零 ✅ 已完成 2026-09-24

### 8.1 根因

复习队列是**句子级**的（SM-2 逐句复习），而 `GrammarLessonPage` 把 guided 各题的
`answer` 直接当句子入队——而 `choose` / `replace` / `spot` 的 answer 是**单个词**
（`am` / `is` / `have`）。单词卡进了句子队列后：

- `rebuild`（词块重组）只剩 1 个词块 → 点一下就过（`rebuildTooFewChunks` 393 处，P0）
- `cloze` 在同族凑不出选项时只剩 1 个选项（`clozeSingleOption` 311 处，P1）

### 8.2 修法（三处联动）

| 处 | 文件 | 改动 |
|---|---|---|
| ① 入队侧（根因） | `lessonService.ts` 新增 `reviewSentenceOfGuidedStep` | `choose` 用 `before`/`after` 还原整句；`arrange` 本就是整句；`replace`/`spot` 因**变换后整句不在数据里**而不入队。`GrammarLessonPage.saveMistakeIfNeeded` 收口：词数 < 2 一律不入队 |
| ② 生成侧（兜存量） | `grammarReviewService.buildGrammarReviewTask` | 单词卡不再一律退 free_type，而是**分流**：`rebuild` 永不用于单词卡；`cloze` 若同族能凑出 ≥2 选项就照常出；凑不出（`dogs`/`went`）才退 free_type |
| ③ 扫描侧 | `gq1-review-tasks.test.ts` | guided 枚举改用**同一个** `reviewSentenceOfGuidedStep`，否则会报出永远不会出现的卡 |

**② 不是我写的**——我最初的版本是「词块 < 2 一律 free_type」，已被并发会话的更优版本覆盖，
我接受并改了测试去匹配。**他们的版本更准**：功能词有同族替换（`buildClozeOptions` 能给出
`["am","is","are"]`），一刀切换 free_type 会**误杀一个本来能用的 cloze**
（rv5-cloze-quality 正是在断言这一点）。我的测试因此改成断言**不变量**而不是具体模式：
单词卡永不 rebuild；单词卡若出 cloze 则选项必须 ≥ 2。

### 11.2 真缺陷：`finishs`

A 类里 `lesson-153-yet-already` / `lesson-180-whole` 的选项含 **`finishs`**（不是英语词，应为 `finishes`）。
成因：加后缀造词的 `-s` 规则一律 `${base}s`，没处理 `-s/-sh/-ch/-x/-z` 结尾要加 `-es`。

全库扫过：**`finishs` 是唯一一例**（370 个去重干扰项里），出现在 2 道题。

**为什么 `fabricatedDistractor` 抓不到它**：那个谓词的 `allowInflection=true` 会先剥词尾再查词典，
`finishs` 剥成 `finish` 就「合法」了。**这是它漏报这类错误的根本原因。**

### 11.3 两处修复

1. **生成侧**（`grammarBoostService.ts`）：`const thirdPerson = /(s|sh|ch|x|z)$/.test(base) ? \`${base}es\` : \`${base}s\`;`
2. **检查侧**（`gq1` / `gq2` 两处 `baseForms`）：剥 `-s` 前先确认「词干 + s」本身是合法变形——
   词干以咝音结尾时不剥（那种情况只能配 `-es`）。

**验收（双向）**：`finishs`/`watchs`/`needss` 现判**非词**；
`finishes`/`needs`/`cleaned`/`wanted`/`plays`/`goes`/`studies`/`hopes`/`tired`/`watching`/`helping`
**全部仍判真词**（重点确认没有过度过滤——先前用内置词典过滤时曾把 `cleaned`/`needs` 整批误伤）。
两个扫描的计数**未变**（gq2 `fabricatedDistractor` 0、gq1 `distractorNotRealWord` 1），符合预期：
第 1 项消掉唯一的实例，第 2 项是防复发。全仓 253 文件 / 2655 条全绿。

### 11.4 这一类问题的总账（值得单独记）

「用词的**形状**判断，而不是用**身份**」已经出了四次：

| 实例 | 形状 | 后果 |
|---|---|---|
| `ned` | 词干还原把 `need` 剥成 `ne` | 非词进了选项 |
| `cleaneding` | 叠两个变形后缀 | 非词（被结构规则抓到） |
| `needing` | 真词被结构规则误伤 | **误报**（`-eed` + `ing` 撞型） |
| `finishs` | `+s` 未处理咁音词干 | 非词，且检查抓不到 |

四次都不是「某个词写错了」，而是**判据本身在近似**。修的时候要同时看两个方向：
既要能抓到造出来的词，又不能误伤合法变形（11.3 的验收就是按这个写的）。

## 16. `huntDuplicateCards` 一案一卡 ✅ 已完成 2026-09-24

## 20. `slotOf` 改用真实词性 + PR1-8 ✅ 已完成 2026-09-24

### 20.1 `slotOf`：第五例「用形状判断身份」

`slotOf` 靠**后缀形状**推词性，于是 `tired`（形容词 a.）被 `/^[a-z]{3,}(ed|d)$/` 判成 **verb-ed**、
`always`（副词 adv.）被 `/^[a-z]{3,}(s|es)$/` 判成 **verb-s**——两个内容词因此被判「槽位不相容」而删掉。

**修法（用真实词性，不再加后缀特例）**：内置词典有 `partOfSpeech` 字段（`n.` / `v.` / `a.` / `adv.`…），
建 `dictPos` 索引（变形先经 `baseForms` 还原到基础形再查），三个「动词形状」的槽位
（`verb-s`/`verb-ed`/`verb-ing`）**只在词典确认是动词时才承认**：

```ts
const verbish = Boolean(pos && VERB_POS.has(pos));
for (const [name, pattern] of SLOT_PATTERNS) {
  if (VERB_SHAPED.has(name) && !verbish) continue;   // tired(a.) / always(adv.) 不再落进动词槽
  if (pattern.test(lower)) return name;
}
```
