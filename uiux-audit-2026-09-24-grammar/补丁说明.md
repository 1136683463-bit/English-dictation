可从这两个补丁恢复。它们**不进入 git 历史**，不改变任何人的归属。

| 事实 | 影响 |

| 我离开时是 20 个脏文件、现在 82 个 | 对方大概率**仍在工作**，此刻不是安全的提交点 |

## 用法

```bash
# 校验补丁与当前树一致（已校验通过）
git apply --check --reverse uiux-audit-2026-09-24-grammar/my-work-pure.patch

# 若工作树被还原，恢复我的工作
git apply uiux-audit-2026-09-24-grammar/my-work-pure.patch
git apply uiux-audit-2026-09-24-grammar/mixed-files-full.patch
```

1. 等对方的 82 个文件**减下来**、或他们提交之后，再提交；
2. 提交时**先** `git apply --check --reverse my-work-pure.patch` 确认补丁与树一致

3. 提交后跑 `npx vitest run`——本轮的验收基线是 **2695 / 2699 通过**，
